# Cloudhal Studio design system

**Binding for every admin surface** (`apps/studio`, capability panels, docs UI). Cloudhal is a premium, community-facing product; its admin must read like the current Cloudflare dashboard. The implementation vocabulary is **Kumo** (`@cloudflare/kumo` 2.14, 54 components + 3 blocks) consumed through `@cloudhal/ui`. The official `kumo-design` skill (`.agents/skills/kumo-design`, installed from `cloudflare/kumo`) is part of this document; `apps/studio/test/design-rules.test.ts` enforces the mechanical rules in CI.

Verified sources: kumo-ui.com (installation, components-vs-blocks, blocks, component docs, registry), the Kumo repository (`sidebar.tsx`, blocks, the docs app shell), the kumo-design skill, Cloudflare dashboard documentation and changelogs (accounts/zones navigation, keyboard shortcuts 2026-05, navigation updates 2025–2026). Date: 2026-10-08.

## 1. Dashboard anatomy

The Cloudflare dashboard is: a **left sidebar** that is the primary navigation and whose contents switch between an *account surface* and a *zone surface* (a switcher sits at the top of the sidebar); **grouped, collapsible menus named by capability, not product**; a slim **top bar** with quick search (`/`, ⌘K) and the user menu; a **content area** with breadcrumbs, a page header (title, description, tabs, right-aligned actions), and **cards or tables**; resource lists carry a sticky right column with usage/help; empty states, skeleton loading, toasts and banners are system-wide.

Studio mirrors this one-to-one:

| Part | Kumo implementation |
|---|---|
| App shell | `Sidebar.Provider defaultOpen collapsible="icon" peekable mobileBreakpoint={768} className="h-svh"` → `<Sidebar>` + a content column `flex h-full min-h-0 flex-1 flex-col overflow-y-auto bg-kumo-overlay`. The provider must have a definite height because Kumo's `<aside>` is `h-full`; the column scrolls, the sidebar stays viewport-tall. Sidebar 16.25 rem expanded, 57 px icon rail. |
| Surfaces | *Account surface* (all sites) and *site surface* (one site); the switcher at the top of the sidebar is a `DropdownMenu` listing sites and "All sites". |
| Top bar | `header.sticky.top-0.z-10.h-12.shrink-0.border-b.border-kumo-hairline.bg-kumo-canvas`: `Sidebar.Trigger` (below `md`, the only way into the sheet), **the page's breadcrumbs** (`PageCrumbsSlot`; Kumo `Breadcrumbs` are `h-12`, exactly the bar), then right-aligned the `CommandPalette` button (⌘K and `/`), the surface's actions (site surface: `SitePublish`, the Publish split button), the notification bell (`NotificationsBell`, §2n) and the language `Select` — all `size="sm"`. |
| Content container | `PageLayout` (`@cloudhal/ui`) — the only container: `mx-auto max-w-[1400px] px-4 py-6 sm:px-6 md:px-8 md:py-8 lg:px-10`, `width="narrow"` caps at 960 px. Screens never set `mx-auto`/`max-w-*` themselves (lint `page-container`). |
| Breadcrumbs | Built only by `Crumbs` / `SiteCrumbs` (`components/Crumbs.tsx`): "Cloudhal Studio › ui-audit › Pages › About", `Breadcrumbs.Current loading`, `Breadcrumbs.Clipboard` for the current resource id. Passed to `PageLayout crumbs`, which portals them into the top bar — never rendered in the content. |
| Page header | Kumo's `PageHeader` block (owned copy: every row flush with the content edge, 14 px description, `icon`, `actions`, controlled `tab`, loading title), rendered by `PageLayout` from its `title`, `description`, `icon` (24 px, top-level list pages only), `actions` (the page's primary action — "New page", "Create key" — lives here, never in the toolbar row) and `tabs`. Tabs are for **sub-views of one page only**; a tab bar that repeats the sidebar is forbidden (the old site tab bar was removed for that reason). |
| Lists | `PageLayout` (+ `aside` for usage/help: the `ResourceListPage` two-column body, 380 px sticky once the content is ≥ 64 rem) + `ListToolbar` (Kumo `Toolbar`, default size so it lines up with `Select`/`Button`) + `LayerCard className="p-0"` + `Table` + `Pagination`; empty → a bare `Empty` in the table's place. |
| Sections | `SectionCard` (`@cloudhal/ui`): Kumo `LayerCard` with the `Secondary` header row (title, optional 16 px icon, `actions` right: count `Badge`, ghost `LinkButton` "View all", small buttons) and the `Primary` body (`description`, `children` in `grid gap-5 px-5 pt-4 pb-5`, `flush` for a `Table`, `footer` row for Save/Discard). Never nested (lint `layer-card-nesting`); never a bare `LayerCard` with hand-made headers. |
| Neutral panels | `InsetPanel` (`@cloudhal/ui`, `outline` / `recessed`) for summaries and quoted agent text inside cards and dialogs ("Now → New", the agent's reason); `Surface` for standalone neutral surfaces. Hand-made `rounded-* ring` divs are forbidden in screens (lint `no-ad-hoc-surface`). |
| Feedback | `Banner` (page/section), `Field`/`Input error` (inline), `Toasty` + `useKumoToastManager` (transient). |
| Confirmation | `ApprovalDialog` (ours, on `Dialog`) for publish/rollback; `DeleteResource` (block) for typed-name deletes; `LayerDialog.Alert` for other destructive alerts. Always rendered, controlled by `open`. |
| Forms & detail sheets | `LayerDialog.Root open onOpenChange` → `LayerDialog.Content` whose **direct** children are `Title`, optional `Description`, `Body`, optional `Actions` (Kumo throws otherwise; branch *inside* each part). Desktop dialog, bottom sheet on phones. |
| Code & config | `CodeHighlighted` from `@cloudhal/ui/code` (Shiki, lazy, `showCopyButton`) for snippets and JSON payloads; `ShikiProvider` lives at the app root (`CodeProvider`, localised copy labels). `Code` stays for one-line CLI hints in usage panels. |

Keyboard parity with the dashboard: `⌘K` / `/` open the palette; `t s` toggles the sidebar; `?` lists shortcuts (palette entry).

## 2. Page templates

Every route file declares one template in `ROUTE_TEMPLATES` (`apps/studio/scripts/design-lint.ts`); the lint then requires that template's blocks. A new screen fails until it is registered.

| Template | Built from |
|---|---|
| `queue` | `PageLayout`, flush `SectionCard`s of `divide-y` rows / a `Table`, `SectionEmpty` (Approvals) |
| `list` | `PageLayout` (crumbs, title, description, `actions`, optional `aside`), `ListToolbar`, `LayerCard p-0` + `Table`, `Empty`, `Pagination` |
| `dashboard` | `PageLayout`, `Columns variant="2-1"`, `SectionCard`s |
| `settings` | `PageLayout`, `SettingsLayout` (sticky `TableOfContents`), `SettingsSection` (= `SectionCard`) |
| `editor` | `PageLayout`, `EditorLayout` (+ `PreviewPanel`), `SectionCard`s |
| `auth` | `AuthLayout` (`@cloudhal/ui`), `Tabs`, `Input`/`PasswordField`, full-width primary `Button`, `Banner` |
| `token` | `AuthLayout` without tabs, `takeHashToken`, `Banner` for the link's state, `SkeletonLine`s while it is inspected, `Input`/`NewPasswordFields`, full-width primary `Button` (`/invite`, `/reset-password`, §2r) |
| `shell` | `AppFrame`, `Sidebar.*`, `SidebarSwitcher` |

```tsx
<PageLayout
  crumbs={<SiteCrumbs siteId={siteId} trail={[{ label: t("pageHeaders.pages.title") }]} />}
  title={t("pageHeaders.pages.title")}
  description={t("pageHeaders.pages.description")}
  actions={<Button variant="primary" icon={<Plus />}>…</Button>}
  aside={<SectionCard title=…>…</SectionCard>}   // optional
>
  …toolbar, cards, tables…
</PageLayout>
```
Reference implementations: `routes/SitesPage.tsx` (list + aside), `routes/PagesPage.tsx` (list), `routes/SiteOverviewPage.tsx` (dashboard), `routes/LoginPage.tsx` (auth).

### 2a. Resource list (sites, pages, articles, snapshots, activity, agent keys, skills)
```tsx
<PageLayout crumbs={…} icon={<Icon size={24} />} title description
  actions={<Button variant="primary" icon={<Plus />}>New page</Button>}
  aside={<SectionCard title="From the terminal" icon={<TerminalWindow size={16} />}>…<Code /></SectionCard>}>
  <ListToolbar search onSearch placeholder actions={…Select filters, RefreshButton…} />
  <LayerCard className="p-0"><Table><Table.Header><Table.Row><Table.Head/>…<Table.Head sticky="right"/></Table.Row></Table.Header>
    <Table.Body>{rows.map(r => <Table.Row key={r.id}><Table.Cell><Link href>{r.title}</Link></Table.Cell>…<Table.Cell sticky="right"><RowMenu /></Table.Cell></Table.Row>)}</Table.Body></Table></LayerCard>
  <Pagination page perPage={25} totalCount setPage controls="full" />
</PageLayout>
```
Empty → a bare `Empty icon={<Icon size={48} />} title description commandLine contents` in place of the table (Kumo `Empty` draws its own frame — never wrap it in `LayerCard`); inside a card, cell or dialog use `SectionEmpty` (frameless). Never pass `className` to `Empty`. Loading → `TableSkeleton` (a `Table.Body`, so always inside `<Table>`). Times in lists are relative (`RelativeTime`) with the absolute time in a `Tooltip`. Every control on one toolbar row has the same height (Kumo default size).

Snapshots: the primary "Create snapshot" opens a `LayerDialog` (optional label `Input` + `Radio appearance="card"`: keep the live site / publish it); publishing continues into `ApprovalDialog` before anything is sent. `SnapshotTimeline` rows keep Compare (ghost) and Publish/Roll back (secondary) in separate trailing columns so actions align, the last one `sticky="right"`; times via its `renderTime` prop (`RelativeTime`).

### 2b. Resource detail / editor
`PageLayout` (crumbs via `SiteCrumbs` with `copy={id}`; title; description = status badge + path in mono; actions = `PreviewToggle`, `StatusActions` — a secondary "More actions" ⋯ `DropdownMenu` with a "Status" group plus Duplicate and Delete, and the next lifecycle step as a labelled secondary button, Publish via `ApprovalDialog` — and the primary Save with `loading`, disabled until dirty) → `EditorLayout`. Main: `SectionCard`s with fields in `Grid 2up/3up` (`items-start gap-x-4 gap-y-5`, inputs `w-full`); page sections are one `SectionCard` each (kind icon + name, id as `InlineCopyText`, ghost square icon buttons with tooltips: move up/down, remove → `ConfirmDialog`), added from an "Add section" `DropdownMenu`. Side: `DetailsCard` (`dl` rows: ID, language, revision, updated as `RelativeTime`…) and `DangerZoneCard` (`secondary-destructive` → `DeleteResource`), both in `EditorLayout.tsx`. Lifecycle = explicit actions, never a status `Select`.

### 2c. Settings / form
Same header; `Columns variant="1-2"` (a fixed 13 rem sticky `TableOfContents` and cards capped at 56 rem, side by side once the page container is ≥ `@4xl`); one `SectionCard` per section, `Switch` for instant settings, `SensitiveInput` for secrets, `ClipboardText` for ids; sticky footer `border-t border-kumo-line` with `Button variant="primary" type="submit" loading`.
Studio implements it as `SettingsLayout` + `SettingsSection` (`components/Settings.tsx`): the `TableOfContents` is sticky from the page container's `@4xl` breakpoint (hidden below it; the cards stack); its label is a sentence-case `Text` with the nav's `aria-label`, never `TableOfContents.Title` (Kumo renders it in capitals) and driven by Kumo's `useTableOfContentsActiveId`; items scroll the content column themselves (no router hash navigation), and a `#section` deep link lands on its card. Each section is a `SectionCard` (`SettingsSection` maps `aside` → `actions`): header (title, optional badge/actions right), body with a muted description, controls carrying their own `label`/`description`/`error`, label/value rows as `dl` (`SettingRow`), and a footer row `border-t border-kumo-hairline` with the section's own actions (ghost "Discard" only while dirty, primary "Save changes" disabled until dirty). Sections save independently. A section holding a `Table` uses `flush` (no body padding). Text inputs in cards get `className="w-full"` so they never overflow the card at 375 px; field pairs use a container-query grid (`@container` → `@lg:grid-cols-2 items-start`), each field with its own description so rows stay aligned.
Saves that `PUT` a whole document send the latest cached copy plus the section's fields; a 409 shows `Banner variant="alert"` "This site changed somewhere else" with `Banner.Action` "Load latest" (the form keeps unsaved edits unless the server's values for those fields changed).

### 2d. Destructive flow
`Button variant="secondary-destructive"` → `DeleteResource open onOpenChange resourceType resourceName onDelete isDeleting errorMessage`. Non-typed destructive confirmations: `LayerDialog.Alert`. Never `{open && <Dialog/>}`.

### 2e. Auth
`AuthLayout` (`@cloudhal/ui`): canvas background, a centred 400 px column — brand row (icon tile + product name), one `Surface` card (`rounded-xl px-6 py-5 ring-kumo-line`) with the heading (`Text heading lg`, "Welcome back" / "Create your account") and description, then the form: segmented `Tabs` (sign in / create account), `Input label` fields at full width, `PasswordField` (show/hide), `Button variant="primary" loading` full width, `ErrorBanner` for failures; a footer row under the card (licence note, language `Select`). No sidebar.

### 2f. Editor with live preview (page and article editors)
`EditorLayout` (Studio) around the 2b form, with `PreviewPanel` (`@cloudhal/ui`) as the preview:
- **content ≥ 64 rem** (container query on `PageLayout`'s `@container/page`, so the sidebar's state counts): two equal columns — the form (main sections, then details and danger zone) left, the preview right, `sticky top-16`, height `calc(100svh - 6rem)`, filling its column (`PreviewPanel fill`). A secondary `PreviewToggle` labelled "Hide preview" / "Show preview" (`Tooltip`, `aria-pressed`) in the header actions hides it; the choice is remembered per browser and the layout falls back to `Columns 2-1`.
- **content < 64 rem**: underline `Tabs` "Edit | Preview" above the content; Edit shows the 2b `Columns 2-1` (stacked on phones).
- `PreviewPanel`: `LayerCard` with a `Secondary` toolbar — heading, status slot (`Badge warning dot` "Unsaved changes" + `Tooltip` when the form is dirty), segmented `Tabs size="sm"` for Desktop/Tablet/Mobile (icon + label, label hidden on phones), `RefreshButton`, `LinkButton external` "open in new tab" — and a `Primary` viewport on `bg-kumo-recessed`. Desktop fills the panel; tablet (768) and mobile (390) render at their real width, scaled down only when the panel is narrower, framed with `ring ring-kumo-line`. Loading = `SkeletonLine` rows in an overlay with `role="status"`.
- The frame is always `<iframe sandbox="">` (no scripts, no same-origin, no forms) on the same-origin `/preview` endpoint; it reloads when the document's `rev` changes (i.e. after every successful save) and on demand. The term editor is the exception that shows unsaved changes: `PreviewPanel live srcDoc` swaps the server's rendering of the draft into the same sandboxed frame (§2p).

### 2g. Credentials (agent keys) — modes, create, one-time reveal
Every key has a **mode** (ADR-0015) — how independently the agent works; scopes stay the hard limit and a mode never grants more. Studio offers the four key modes, in order of autonomy: `plan` (read + preview), `manual` (every change waits), `edits` (default: edits free, publish/rollback/delete wait), `auto` (like edits, small article-only publishes go live without a person). `bypass` is never offered or sent for a key (the API answers 400); it is only *explained*, with `cloudhal mcp --mode bypass`.

List page per 2a (`PageLayout`, crumbs Agents › Keys and MCP, "Create key" in `actions`; the elevated-keys banner sits between the toolbar and the table; empty = bare `Empty` with `commandLine` + secondary Create key): name + key prefix (`start…`, mono) in one cell; **Mode** column with `ModeBadge` (while elevated: `KeyModeCell`, see *Elevation* below); scopes — one outline `Badge` "Mode default · n scopes" (scopes in its `Tooltip`) when they equal the mode's prefill, otherwise the full `ScopeBadge` list (a `Tooltip` per scope), so customised keys stand out; created/expiry; status dot; row `DropdownMenu` (Change mode, Elevate temporarily, End elevation now while one runs, Copy key ID, separator, Revoke). The `aside` holds the `SectionCard` "Connect an MCP client": endpoint and header as `ClipboardText`, segmented `Tabs` over ready-to-paste client configs in `CodeHighlighted` (the local tab uses `cloudhal mcp --mode edits`); the copy says the agent is told its mode when it connects. Then the compact **"How modes work"** flush `SectionCard`: one-line description, a compact `Table` (Mode × Content / Publish / Rollback, delete) whose cells are dot `Badge`s — Blocked neutral, Waits warning, Free success, "Small: free" success — each with a `Tooltip` explaining the rule, then the tools that always wait with a key (rollback, delete_page, delete_entry; label + mono name), a `ClockCountdown` line recommending a temporary elevation over a permanent Auto key, and the local bypass command. The table overrides Kumo's cell padding to `px-1` (first/last column `pl-5`/`pr-5`) so four columns fit the 380 px side column and a phone in English and Turkish; keep labels short.

**Mode picker** (`ModePicker`, `components/AgentModes.tsx`) — the one way to choose a mode:
- `Radio.Group appearance="card"` (legend visually hidden via `Radio.Legend className="sr-only"`), one `Radio.Item` per key mode, iterating `KEY_MODES` (never a literal list; CI checks).
- Card `label`: mode icon (Phosphor: plan `Eye`, manual `UserCheck`, edits `PencilSimple`, auto `Lightning`, bypass `LockSimpleOpen`, 16 px, `text-kumo-subtle`), the name, a **risk `Badge`**: plan/manual `success` + `ShieldCheck` "Safest", edits `info` + `Star` "Recommended", auto `warning` + `Warning` "Use with care"; in the change dialog the key's current mode adds an outline "Current".
- Card `description`: one line on behaviour, then a `HandPalm` line "**Waits for you:** …".
- `BypassHint` under the cards; `edits` preselected.
- Choosing `auto` (where it is not already the mode) shows `AutoModeConfirm`: `Banner variant="alert"` with a `Lightning` icon explaining the low-risk rule (articles only, nothing removed, ≤ 20 changes, marked auto-approved, one-click rollback), and a `Checkbox` "I understand that this agent can publish without my approval" that must be ticked; the primary action shows an inline error otherwise. CI checks that every screen rendering `ModePicker` also renders `AutoModeConfirm`.

`ModeBadge`: filled, semantic tone by autonomy — plan `secondary`, manual `success`, edits `info`, auto/bypass `warning` — with the mode icon and a `Tooltip` (behaviour + what waits). `subtle` renders it `outline` for dense audit cells so the decision badge stays loudest. Carries `data-mode`.

Create = one `LayerDialog`, three states in the same parts (no fragments in `Content`):
1. **Mode** (step 1 of 2): the mode picker (+ auto consent, bypass hint). Primary "Continue".
2. **Name and scopes** (step 2 of 2): an `InsetPanel layout="row"` summary (Mode + `ModeBadge`, "Waits for you: …", secondary "Change" back to step 1), `Input` name (+description, inline `error` after a submit attempt), then `Collapsible` **"Advanced: scopes"** — closed by default, a "Customised" `Badge info` in the trigger when the set differs from the mode's prefill. Inside: "Prefilled for {mode} mode…" hint, ghost "Use the mode's scopes" reset when customised, the scope `Checkbox`es grouped in labelled `InsetPanel`s (Read / Write / Publish and roll back, hint per group, raw scope in mono), and `Banner variant="secondary"` when scopes the mode needs are missing. Changing the mode re-fills the scopes. The request sends `{name, mode}` and adds `scopes` only when customised (the server prefills from the mode). Primary "Create key" (`loading`); dismissal disabled while pending. No `<form>` element around Kumo `Checkbox` (it is a `<button>` and would submit) — Enter in the name field submits.
3. **Reveal**: `Banner variant="alert"` "You won't see this key again", the key in `ClipboardText size="lg"`, the client config with the key filled in (`CodeHighlighted` + copy). Primary "I've stored the key". The plaintext lives only in component state and is dropped when the dialog closes.

Change mode = `LayerDialog` from the row menu (`ChangeAgentModeDialog`): the mode picker starting at the current mode, bypass hint, auto consent, then — right above the action — an `InsetPanel` "Now [ModeBadge] → New [ModeBadge]" with "Applies on the agent's next call" (running calls finish in the old mode; the change is audited). Primary "Change mode" is disabled until the mode differs. A refusal (400) stays in the dialog as `Banner variant="error"` with the server's message; success closes it, shows a success toast "{name} now works in {mode} mode." and refetches the list.
Revoke = `DeleteResource` with `deleteButtonText` "Revoke key", success toast.

**Elevation** (ADR-0016) — a key works in a more autonomous mode for a while, then returns to its own mode by itself. The icon for anything time-boxed is Phosphor `ClockCountdown`.
- **Row menu** "Elevate temporarily" sits under "Change mode". For a key whose own mode is already `auto` nothing is above it (bypass is local), so the item is `disabled` with a `Tooltip` "Already in Auto…" (the tooltip hangs on a `render={<div />}` wrapper because a disabled Kumo menu item takes no pointer events). Never hidden.
- **Elevate dialog** (`ElevateAgentKeyDialog`, `LayerDialog size="base"`), top to bottom: an info `Banner size="sm"` "This replaces the elevation in force" when one runs (with its mode and end); "Own mode [ModeBadge]" with "Stays as it is"; a visible "Elevate to" label over `ModePicker only={modesAbove(own)}` — cards with nothing to offer are absent, the next mode up is preselected; `AutoModeConfirm` whenever the target is `auto` (also when replacing an Auto elevation); **Duration** as a `fieldset` with segmented `Tabs` presets 15 min / 1 hour (default) / 4 hours / 1 day / Custom — presets outside the server's `agentModes.elevation` bounds are dropped; Custom shows `Input type="number"` (label, "Between 5 minutes and 1 day." description, inline `error` "At least …"/"At most …" while typing, "Enter a number" after a submit attempt) next to a `Select` Minutes/Hours (hours accept a decimal comma, rounded to whole minutes); **Reason** `Input` (optional, ≤ 200 characters, "Shown in the audit log."). Right above the action, the `InsetPanel` summary: "Now [own] → Elevated [target]", then `ClockCountdown` + bold "Until 14:30 (in 1 hour), then back to Edits." (`elevationSummary`: today → time only, within the week → weekday + time, else date + time; the person's locale and time zone) and "Applies on the agent's next call. You can end it early from the key's menu." A 400 stays in the dialog as `Banner variant="error"` with the server's message; success closes it, toasts "Desk works in Auto mode until 14:30, then back to Edits." and refetches. Primary "Elevate" (`loading`), dismissal disabled while pending.
- **Mode cell while elevated** (`KeyModeCell`): the elevated `ModeBadge`, then an outline `Badge` with `ClockCountdown` "42 min left" (short units, nearest minute, at least 1) whose `Tooltip` reads "Elevated from Edits until 14:30 by you" plus the reason in quotes; under them `Text xs secondary` "Own mode: Edits", so the key's own mode stays recognisable. One line (`whitespace-nowrap`); the table scrolls sideways on phones. The page re-reads the clock every 30 s (`useNow`) and schedules a refetch one second after the earliest end (`useElevationExpiry`); a cell whose end has passed shows the own mode even before the refetch lands.
- **Summary banner** (`ElevatedKeysBanner`, top of the list, `role="status"`): "1 agent key is elevated" / "n agent keys are elevated", one line per key "Desk: Edits → Auto until 14:30", `Banner.Action` "End now" (or "End all now"). `alert` tone when any key is elevated to Auto, `default` otherwise. Keys inside the notice window (`agentModes.elevation.noticeMinutes`, 10) add a warning `Badge` with `ClockCountdown` "Ends in 8 min" to their line, and the banner adds `Banner.Action` "Extend 1 hour" (several: "Extend all 1 hour") before "End now" — the same `useExtendElevation` as the bell (§2n). The actions wrap under the text on phones. In the key's Mode cell the timer badge turns `warning` inside that window.
- **End now** (row menu, banner) acts immediately with a success toast "Elevation ended · Desk is back in Edits mode." — no confirmation dialog: it only takes autonomy away, is audited, and elevating again is one dialog away (the same reasoning as approving a non-destructive request, §2m). Failures are error toasts.
- **Agents ask** (ADR-0016 addendum): on servers reporting `features.elevationRequests`, a key whose agent waits for an elevation shows a dot `Badge warning` "Asks for Auto" under its mode, a `Link` to that site's Approvals with a `Tooltip` ("Desk asks to work in Auto mode for 1 hour. Open Approvals to decide."). It reads each site's pending list through the same cached query the site surface polls (`usePendingElevations`), without polling of its own. A grant made from a request keeps the agent's words as the key's reason; the timer tooltip renders it as "Requested by the agent: “…”".
- **Change mode while elevated**: an info `Banner size="sm"` at the top of the dialog, "Elevated to Auto until 14:30", whose description follows the selected card — "The elevation stays in force until 14:30, then the key works in Manual mode." while the new own mode is still below the elevation, "Auto reaches the elevated mode, so this change ends the elevation." otherwise (the server's rule). The list is updated from the returned summary as a whole, so an ended elevation disappears at once.

### 2h. Audit log (site › Activity)
Toolbar row: `ListToolbar` (search `Toolbar`, default size: tool, label, actor, skill) with, on the right, a ghost "Clear filters" (only while filtered), a `Toolbar` of `Select render={<Toolbar.Button />}` per facet (actor type, decision) and a `RefreshButton`, all at the default height. Empty and filtered-empty are a bare `Empty` in the table's place. `LayerCard p-0 overflow-x-auto` + `Table`, columns in reading order: Tool (localised imperative label, raw MCP name in mono below), Decision (`DecisionBadge`: filled, icon; allow = success, approval-required = warning, deny = error; an `auto`-mode publish that went live without a person — `autoCheck.lowRisk` on an allow row (older rows: reason starting "auto mode: published without approval") — adds `AutoApprovedBadge`, `warning` + `Lightning` "Auto-approved" with a localised tooltip; both via `DecisionCell`, also on the overview's recent activity), Actor (`ActorBadge` + name + the mode the call ran under as a subtle `ModeBadge`; people have none; a call made under a time-boxed elevation — `elevation: {from, until}` on the row — gets a `ClockCountdown` marker inside the badge (`role="img"`, label "Temporarily elevated") and its tooltip leads with "Temporarily elevated from Edits until 14:30"), When (relative, absolute in `Tooltip`), Outcome (`OutcomeBadge`, dot), Skill, Snapshot (link to the diff), sticky chevron `Button` that opens the row. The whole row is clickable for pointer users; the chevron is the keyboard path. Paging is cursor-based: `useInfiniteQuery` over `nextBefore`, a footer with "Showing n of m loaded events" and a secondary "Load more" (`loading`), or "You've reached the first recorded event". Filters apply to loaded rows and say so in the filtered-empty state. Search also matches the mode. Detail = `LayerDialog size="lg"`: reason as a `Banner` (error for deny, alert for approval; for an auto-approved publish an alert "Published without a person" with the article count, replacing the raw reason), a `dl` of facts (including **Mode** with a full `ModeBadge`, and for elevated calls an **Elevation** row: "Temporarily elevated from Edits until <absolute time>" with a muted line on the key's own mode) separated by `divide-kumo-hairline`, the input JSON in `CodeHighlighted`, "View changes" → snapshot diff. People's actions on keys have labels too (`agent-key.elevate` "Elevate agent key", `agent-key.mode`, `agent-key.elevation-end`); a grant row adds, under the tool name, subtle "[Edits] → [Auto ⏱]" badges (`ElevationGrant`) and an outline `Robot` badge "Requested by the agent" when its reason ends with "requested by the agent (appr_…)"; its detail adds an **Elevation granted** row (badges, "Auto mode until <absolute time>, then back to Edits.", the request id as `InlineCopyText`). The overview page shows the five newest events in a compact "Recent activity" card with "View all".

### 2i. Snapshot diff

### 2m. Approvals (site › Approvals; sidebar History › Approvals with a count)
Agents with keys cannot approve their own publish / rollback / delete (ADR-0014): the request waits here for a person. Agents in `manual` mode (ADR-0015) also send every content edit here; those requests (`cause: "manual-mode"`; older servers: reason starting "manual mode:") are not shown with the server's terse reason but replaced by a localised sentence with a `ModeBadge mode="manual"` ("{agent} works in Manual mode, so this change waits for you: Update article.") plus a muted hint, and by "Manual mode: {tool}" in History; they approve directly (no confirmation dialog), like any non-destructive tool. Every other request shows its `mode` as a subtle `ModeBadge` before the prompt; an `auto`-mode publish the low-risk rule held back (`autoCheck.lowRisk === false`) adds a muted line saying why in the person's language ("Auto mode publishes small article updates on its own. This one waits for you because it changes pages, site settings, taxonomies or redirects."). Activity and Approvals are separate sidebar items; the pending count appears on the sidebar `MenuBadge` and the overview banner from one query, refresh is in the page header actions, polled every 15 s (`refetchInterval`) only while the site shell is mounted; a 404 (approvals off) stops polling and shows `Banner variant="secondary"`.
- **Waiting for you**: one flush `SectionCard` (HandPalm icon, description) with `divide-y` rows (no nested cards): `ToolCell` (localised label + raw name), `ActorCell` (`ActorBadge` + name), Deny (secondary) / Approve (primary) with `loading`, the server's prompt as **plain text** (it can quote agent-written titles; never HTML — CI checks there is no `dangerouslySetInnerHTML`), requested / expires as `RelativeTime` with a warning `Badge` under an hour, and `Collapsible` arguments in `CodeHighlighted`. Ordered by expiry. Empty: `SectionEmpty` "Nothing is waiting for you".
- **Approve** on `publish`, `rollback`, `delete_page`, `delete_entry` opens `ApproveRequestDialog` (`LayerDialog`): the prompt in an `InsetPanel`; for publish the approximate changes (live snapshot → newest snapshot: count badges + "View changes", labelled as an approximation because edits after the newest snapshot are not counted); for rollback the target snapshot with "View changes"; for deletes the target id; and an info `Banner` "Single use, for the site as it is now" (void if anything changes before the agent calls again). `request_elevation` has its own dialog (below). Other tools and Deny act immediately with a toast.
- **409** (decided, used or expired meanwhile): error toast "This request is no longer pending", the dialog closes, the list refetches.
- **Elevation requests** (`tool: "request_elevation"`, ADR-0016 addendum; `ElevationRequest.tsx`) are a different kind of request and look it. The server's English prompt is never shown. The left cell is laid out like `ToolCell`: a 16 px `ClockCountdown` icon with "Elevation request" and the raw `request_elevation` in mono below; History uses the same cell. The body shows, in order:
  - the change as two full `ModeBadge`s, "Edits → Auto". The own mode comes from `/api/agent-keys` (`input.keyId`), else the prompt's "its own mode is …", else the request's `mode` (`requestOwnMode`);
  - a localised sentence, "Desk asks to work in Auto mode for 1 hour.";
  - the agent's reason as `AgentReason` (recessed `InsetPanel`) labelled "The agent's reason", quoted, as **plain text** (agent-controlled);
  - a muted line on what approving does. When the key's own mode has caught up with the request meanwhile, `Banner variant="secondary" size="sm"` instead says there is nothing to grant and to deny it;
  - in the meta row, `ClockCountdown` "If you approve now: until 14:30".

  **Approve** always opens `ApproveElevationDialog` (`LayerDialog size="base"`); **Deny** stays one click. Top to bottom, the dialog has:
  - `AgentReason`;
  - **Mode** with the requested `ModeBadge`, fixed (no picker), and "To grant another mode, deny this request and elevate the key from Agents.";
  - `AutoModeConfirm` when the mode is `auto`;
  - **Duration**: "Requested: 1 hour. Shorter is fine, longer isn't possible.", then segmented `Tabs` with the standard presets shorter than the request plus the request itself, preselected (`grantPresets`; an odd request reads "1 hr 30 min" in the presets' words), then Custom. Custom has the elevate dialog's number + unit fields, bounded by the server minimum and the request ("At most 1 hour");
  - an outline `InsetPanel` summary "Now [own] → Elevated [mode]", the bold "Desk works in Auto mode until 14:30, then back to Edits." and "Applies on the agent's next call…".

  The primary action is "Grant elevation" (`loading`). The POST sends `{minutes}` only when shortened. Errors:
  - A **400** stays in the dialog as `Banner variant="error"`.
  - A **409** shows the server's message plus "The request stays in the list while it is pending…", and refetches approvals and keys. If the refetch shows the request is no longer pending, the dialog closes with the "no longer pending" toast.

  On success, a toast "Elevation granted · Desk works in Auto mode until 14:30, then back to Edits." and approvals, agent keys and activity are invalidated. CI checks that the dialog is the only caller of `api.approvals.grantElevation`, renders `AutoModeConfirm` with its guard, never sends more than requested, and that the page routes elevation approvals to it first.
- **History**: flush `SectionCard` (ClockCounterClockwise icon) with a `Table` (or `SectionEmpty`): request (tool + truncated prompt in a `Tooltip`), status dot `Badge` (approved success, denied error, used neutral, expired warning), agent, requested, decided (time + "by you" or the deciding actor id). Elevation requests read `ClockCountdown` "Elevation request" over "Elevation to Auto · 1 hour" (the requested time), and a used one is "Granted" (success).
- **Overview**: while requests wait, `Banner variant="alert"` with a hand icon and `Banner.Action` "Review requests" above the cards.

### 2n. Notifications (top bar bell; ADR-0016 addendum "told before it ends")
`GET /api/notifications` lists what needs the signed-in person: their elevations ending within `noticeMinutes` (`elevation-ending`) and agents asking to elevate one of their keys (`elevation-request`). Items carry stable ids. Studio reads it with one query (`useNotifications`, key `["notifications"]`), owned by the bell, so it runs only while someone is signed in: every 60 s, every 15 s while an elevation is ending, also in a background tab (`refetchIntervalInBackground`) so browser notifications can arrive. A 404 (older server) is "no notifications": nothing is fetched again — not on an interval, on focus or on remount.
- **Bell** (`NotificationBell` block, `@cloudhal/ui`): a ghost square `Button size="sm"` with a 16 px `Bell` in the top bar, between the surface's actions and the language select, on every surface and at every width. A count `Badge variant="primary"` sits on its corner (hidden at 0, "9+" above 9); the button's name carries the count ("Notifications (2)").
- **Panel**: Kumo `Popover` (`align="end"`, `positionMethod="fixed"`, 24 rem, at most the viewport minus 1 rem) without its own padding: a header row (`Popover.Title` "Notifications", a secondary count `Badge`), a scrolling list of `NotificationItem`s divided by `divide-kumo-hairline` (max 32 rem / 70 svh), and a footer row with a ghost "Notification settings" that opens Account › Notifications. Empty: `SectionEmpty` with `BellSimple` "You're all caught up". Items whose end or expiry has passed drop out before the next poll.
- **`NotificationItem`**: a 16 px tone icon aligned with the first line (`warning` `ClockCountdown` for an ending elevation, `info` `Robot` for a request), a bold title with optional meta on the right, the body, then one row of `size="sm"` actions that wraps on phones.
  - *Elevation ending soon*: `ModeBadge` of the elevated mode + warning `Badge` `ClockCountdown` "8 min left" (recomputed from `until`), then "Desk's Auto mode ends in 8 min (14:30), then back to Edits." Actions: a `ButtonGroup` — secondary "Extend 1 hour" and a ▾ `DropdownMenu` with a "Counts from now" group of 30 min / 1 hour / 4 hours, each with its new end ("4 hours · until 18:30"); secondary "End now"; ghost `LinkButton` "Open Agents". Extend and End disable each other while pending.
  - *Agent asks*: "Planner asks for Edits · 30 min" with `RelativeTime` as meta, the reason in `AgentReason` (recessed `InsetPanel`, **plain text**: agent-controlled), and a secondary `LinkButton` "Review" to that site's Approvals.
- **Extend = re-post the mode in force** (`useExtendElevation`, `components/Elevation.tsx`): `POST /api/agent-keys/:id/elevation {mode, minutes}` with the elevated mode and the preset clamped to the server's bounds; it replaces the elevation in force and counts from now. The keys are read first, and an elevation that has ended or changed mode is refused with an error toast ("This elevation has already ended") — re-elevating is a new grant, and new grants (with the Auto consent) only happen in the elevate dialog. **End** is `useEndElevation`. Both toast, update the key list and invalidate `agent-keys`, `notifications` and `approvals`; deciding an approval invalidates `notifications` too. The bell, its toasts and the Agents banner never call the API for elevations themselves (CI checks).
- **One-time toasts** (`useNotificationAlerts`, hosted by the bell): an id seen for the first time while Studio is open raises a notice toast once — `warning` "Desk's Auto mode ends in 8 min" / "At 14:30 it goes back to Edits…" with the actions "Extend 1 hour" and "Open Agents"; `info` "Planner asks for Edits · 30 min" with the quoted reason and "Review". The toast carries the item's id (Kumo shows an id once), stays 15 s, and an action closes it. Whatever is there on the session's **first** answer is not announced (the bell lists it). Announced ids are remembered per browser in `localStorage` (`cloudhal.studio.notifications.shown`, last 200, every access in `try/catch`), so a reload never repeats one. New items also refresh the key list or approvals.
- **Browser notifications** (opt-in, Account › Notifications): turning the switch on calls `Notification.requestPermission()` from the click; the choice lives in `localStorage` (`cloudhal.studio.notifications.browser`). For each newly announced id, when the person opted in, permission is `granted` and `document.visibilityState !== "visible"`, Studio raises `new Notification(title, {body, tag: id})` with the toast's words; clicking it focuses the window and opens Agents or the site's Approvals. A visible tab gets only the toast. Delivery beyond an open tab (email, push) is not Studio's job yet.

### 2s. Role gating (RFC-0005 I16)
The server decides; Studio only hides or disables what it would refuse **and says why**.
- **Source**: `GET /api/me` (`useMe`, query `["me"]`) — `role`, `scopes`, the `can` ability map, `invitableRoles`. `useCan(ability)` reads it; anything not known to be denied (loading, older servers) reads as allowed. `useGate(ability)` adds the reason, built from the least senior role that has the ability (`minimumRole` over `/api/instance` → `roles`): "Only Editors and above can publish others' work." Screens never compare role names (CI checks); only the Team screens do.
- **Patterns**: a gated `Button` is `disabled` with `title={gate.reason}` (Kumo wraps a disabled titled button in a `Tooltip`; CI checks every `disabled={!x.allowed}` carries its reason); a gated menu item stays in place, disabled, its `Tooltip` on a `render={<div />}` wrapper; a screen the person may read but not change gets `ViewOnlyBanner` (secondary, `LockSimple`, "You can view this" + the reason) and its controls go inside `ReadOnly` (a disabled `<fieldset>`: inputs, buttons and menu triggers off at once, links still work). Sidebar items stay enabled: every member may read every screen.
- **Where**: pages and the page editor (`pages.write`), categories/tags, the term editor and redirects (`structure.write`), site settings General and Domains (`settings.write`; preview links stay), the tags migration (`settings.write`), others' articles (`entryAccess`: Editors any, Authors their own, Contributors their own until published — the editor shows `ViewOnlyBanner` and a disabled fieldset, and the articles list disables Delete).
- **Publishing** (`usePublishMode`, `usePublishSite` in `components/Publish.tsx`): Editors and above "Publish"; an Author "Publish" when Studio's guess (`ownOnlyGuess`: only their own published articles changed since the live snapshot) says own-only, else **"Request publish"** with its own confirm copy ("Your changes include work by others…", "Send request"); a 202 shows an info notice "Publish requested — an Editor must approve" with "Open Approvals". A Contributor sees Publish disabled with the reason; in the article editor the draft step reads **"Submit for review"** and Publish stays disabled ("An Editor publishes yours after review"). Snapshot rows use `SnapshotTimeline`'s `publishDisabledReason` / `rollbackDisabledReason`.
- **Approvals**: `canDecide === false` disables Approve (and Deny, unless it is the person's own or their agent's request) with a reason line under the meta (`approvals.decide.*`: own request, not the key's creator, mode above the role, missing scope, not own); a 403 `cannot_decide` toasts the same words. A person's own request (cause `role`) shows a warning `Badge` `Hourglass` "Waiting for an Editor", "{name} wants to publish the site." and why their role can't alone (from the server's reason), and **Withdraw** instead of Deny/Approve. Approving such a request publishes it ("Approved and published"); 409 `state_changed` says the site moved on. People's names carry their `RoleBadge` (from `GET /api/members`) here and in Activity.
- **Agent keys**: `useAgentModeRules` carries the person's cap — `keyModes` stops at it (a Contributor's picker shows Plan, Manual, Edits and `RoleCapHint` "Your role allows agent keys up to Edits mode"), elevations offer only modes up to it, and the Elevate item is disabled with that reason. The scope picker shows each scope as the role grants it (`scopeOptions`): an own variant in place of the full scope ("Your role gives content:write only for your own work"), or the scope disabled ("Your role can't give this to a key"). A key whose `effectiveScopes` are narrower than its stored scopes shows the effective ones with a warning `Badge` "Narrowed by role" (tooltip: the creator's role now, and what it was given). Administrators get **Your keys | All keys** tabs; All keys lists every key with a "Created by" column (`Avatar`, name, `RoleBadge`) and a menu with End elevation and Revoke, while Elevate stays disabled ("Only the person who created this key can elevate it").
- **Activity**: without `audit:read` a secondary `Banner` "Your activity — Editors and above see everyone's".
- **Notifications** (§2n): `member-joined` (success `UserPlus`, "Ada joined", the role badge, "Open Team") and `role-changed` (info `ShieldStar`, "Your role is now Author", Editor → Author badges, who changed it); a new `role-changed` refetches `/api/me`, the members and the keys, so gating follows at once.
- **Account**: the profile shows the person's role as a `RoleBadge` row; the account menu's header shows the name and the role.

## 4. Typography, spacing, colour
- **Text only through `Text`**: body 14 px (`size="base"`), `xs` 12 / `sm` 13 for captions, `lg` 16 only for headings; `variant="heading"` (16 px) and `size="lg"` (20 px) for page-level; page titles come from the blocks. Sentence case; product names title-cased; `bold` prop for emphasis; never `font-bold`, never `tracking-*`, never uppercase.
- **Spacing**: `gap-1.5` between a heading and its description, `gap-6` between blocks, card padding `px-5 py-4`, page container `p-6 md:p-8 lg:px-10 lg:py-9`, `max-w-[1400px]`.
- **Colour**: semantic tokens only — surfaces `bg-kumo-canvas|base|elevated|recessed|tint|overlay|contrast`, brand `bg-kumo-brand`, status `kumo-info|success|warning|danger` (+`-tint`), text `text-kumo-default|strong|subtle|inactive|placeholder|inverse|link`. No raw Tailwind colours, no `dark:` (Kumo themes via `light-dark()`; toggle with `data-mode="dark"`). Studio follows the OS scheme: an inline script in `index.html` sets `data-mode` on `<html>` before first paint and tracks `prefers-color-scheme`. The only fixed colours allowed are inside the preview frame, which shows the visitor-facing site (its own theme) on a light canvas.
- **Semantic badge colours**: decisions and outcomes use the status variants (success / warning / error); actor kinds and scope groups use tints (`info`, `secondary`, `outline`, `warning` for publish/rollback scopes) — never the saturated `purple`/`blue`/`neutral` fills, which out-shout the status column.
- **Edges**: `ring ring-kumo-line` (elevated) / `ring-kumo-hairline` (flat); never `border` + `shadow`; concentric radii (`rounded-xl p-1` → `rounded-lg`); sticky elements separate with `border-b border-kumo-line`; no `transition-colors` on hover.
- **Icons** (Phosphor): 16 px in nav, inline text, toolbars, card headers; 20 px icon-only buttons; 24 px top-level list-page title (`PageLayout icon`); 48 px `Empty`; `weight="fill"` only for status (banners, toasts). Icon-only buttons need `aria-label` and `shape="square"`.

## 7. Anti-patterns (CI-enforced where mechanical)
**Enforcement.** `apps/studio/scripts/design-lint.ts` holds the per-file rules (raw elements, class rules, entry points, ad-hoc surfaces, page anatomy, dialog rendering, card nesting, i18n, route templates). It runs three ways: in CI through `apps/studio/test/design-rules.test.ts` (`pnpm check`), by hand with `pnpm design:lint [files…]`, and **on every file an agent writes** through the Claude Code hook in `.claude/settings.json` (exit 2 sends the violations back to the agent at once). Biome additionally forbids `@cloudflare/kumo`, `@base-ui/react` and other icon sets in `apps/**`. When a rule blocks something Kumo cannot express, the answer is a new block in `packages/ui/src/blocks` (with the same rules), never an exception in a screen.

Raw `<table>/<h1>/<button>/<input>/<select>/<a>/<ul>/<p>` in screens; hand-rolled sidebars, headers, cards; raw Tailwind colours; `dark:`; `font-bold`, `tracking-*`, uppercase headings; hover colour transitions; `border` + `shadow`; nested `LayerCard`; conditionally rendered dialogs; status mutation through `Select`; `DANGEROUS_className` to restyle Kumo; a `Tooltip` used as a menu/popover trigger (`Trigger render={<Tooltip …/>}` swallows the trigger's props — nest it the other way, `<Tooltip render={<DropdownMenu.Trigger render={<Button/>}/>}/>`); hard-coded English (every string through `useT()`; Kumo's own labels through `KumoLocaleProvider`); spinner-only pages; uniform `p-5` card padding; a raw `<iframe>` in a screen or any iframe without `sandbox=""`; fragments or conditionals directly inside `LayerDialog.Content`; a `<form>` around Kumo `Checkbox`/`Switch` (they are buttons and submit it); past-tense labels for audit events ("Deleted page" for a call that was denied) — use the tool's imperative name; a top bar that can shrink (`shrink-0` on sticky bars inside flex columns); rendering agent- or server-supplied text (approval prompts, skill descriptions) as HTML — always plain `Text`, never `dangerouslySetInnerHTML`; letting a self-approved action skip the person (approvals are decided only in Studio, ADR-0014); offering or sending `bypass` for an API key, a mode list that is not `KEY_MODES`, or letting a key become `auto` without the explicit consent checkbox (ADR-0015); offering an elevation to a mode that is not above the key's own, or elevating to `auto` without that same checkbox (ADR-0016); extending with any mode but the one in force, re-elevating a key whose elevation has ended from a notification, or changing an elevation outside `useExtendElevation`/`useEndElevation`; announcing a notification twice, or announcing what was there on the session's first load (§2n).

## 8. Review checklist
Before merging UI: `pnpm design:lint`; look up components with `pnpm kumo ls` / `pnpm kumo doc <Name>` / `pnpm kumo blocks` before writing markup; screenshot every touched screen at 1440 and 390 px with `pnpm design:shots -- <routes>` (headless Chrome against your dev server; fails on sideways scrolling or console errors; `SHOTS_SCHEME=dark|light` and `SHOTS_LOCALE=tr` for both themes and Turkish; for role-gated screens, one run per role's test account) and compare against this document; run `pnpm --filter @cloudhal/studio test` (design rules); confirm every new string exists in `en.ts` and `tr.ts`; confirm the kumo-design rules (14px, sentence case, tokens) by reading the diff.
