# Cloudhal threat model (alpha)

Cloudhal lets AI agents change websites. The central security promise: **an agent can only do what its scopes allow, every change is recorded and reversible, and nothing goes live without a person.** This page lists who can do what, the controls behind each promise, and the risks we accept for the alpha. Report vulnerabilities as described in [SECURITY.md](../../SECURITY.md).

## Principals
Staff roles are named sets of scopes (RFC-0005, ADR-0018). A person's role is read from their single membership on every request; without one they have no scopes.

| Principal | How it authenticates | Can do |
|---|---|---|
| Owner | Better Auth session cookie (Studio) | Everything (`*`), including transferring ownership; exactly one per deployment |
| Administrator | Session cookie | Every non-wildcard scope: content, structure, publish, rollback, site settings and domains, members (non-Owner), invites up to Administrator, others' agent keys (revoke, end elevations) |
| Editor | Session cookie | Content, pages, taxonomies, redirects, publish, rollback, all Activity; invites Contributors and Authors |
| Author | Session cookie | Own articles in any status; publishes own-only change sets (anything wider becomes a request an Editor decides) |
| Contributor | Session cookie | Own never-published drafts (draft/review); proposes tags; never publishes |
| Agent | API key (`x-api-key`) with explicit scopes | MCP tools only, within its scopes narrowed to its creator's current role; publish/rollback/delete wait for a person |
| Local developer's agent | `cloudhal mcp` over stdio | All scopes on the local project; gated tools ask in the MCP client |
| Operator | Deployment token (bearer) | Export/import whole sites (`cloudhal push/pull`); recover ownership (`cloudhal owner transfer`) |
| Site visitor | — | Published pages; drafts only with a signed preview link |

## Promises and controls
1. **Agents stay inside their scopes, and an agent never exceeds the person whose key it uses.** Agent principals are refused on the REST API (403 everywhere except `/api/me`); MCP calls pass the policy engine (scopes × tool annotations × declared skill). A key's scopes must fit its creator's role when it is minted, and on every call they are narrowed to the creator's *current* role; a key whose creator is no longer a member is refused (401). Key modes and elevations are capped by the role (Contributor: `edits`); only the key's creator grants an elevation. Person-only scopes (`site:settings`, `members:*`, `agents:manage`, `audit:read`) never sit on a key. Keys cannot mint keys; permissions are server-only, and Better Auth's own `/api/auth/api-key/*`, `/api/auth/organization/*` and `/api/auth/admin/*` endpoints answer 404. Per-key rate limit 600/min.
2. **Nothing goes live without a person, unless the owner chose otherwise.** Publish, rollback and delete create a pending approval that a signed-in person decides in Studio (ADR-0014). The only exception is a key the owner put in `auto` mode, permanently or for a bounded time (5 min to 24 h, ADR-0016): it may publish article-only changes (nothing removed, at most 20) without a person (ADR-0015). Rollback and delete always wait. Modes are owner-only, never grant scopes, `bypass` is local only, and an elevation ends by itself because the mode is computed on every call. An agent may *ask* for an elevation (`request_elevation`), but only a signed-in owner of its key can grant it, for at most the time asked. Approvals are single-use and bound to the tool, exact arguments, the requesting agent and the content state; any change after the question voids them. Agents never receive a redeemable token.
3. **Every change is recorded and reversible.** Each MCP mutation snapshots the site; every tool call and decision is written to the audit log; rollback moves the published pointer to an ancestor snapshot.
4. **Agent-written content cannot run code.** Agents write markdown only (no HTML sections, no edits to HTML bodies); markdown escapes raw HTML; links and image sources are limited to safe schemes; site responses carry a CSP without inline or third-party scripts.
5. **Studio sessions are not usable cross-site.** State-changing `/api` requests must be same-origin; cookies are HttpOnly + SameSite=Lax; `/mcp` refuses foreign origins; a server without auth only answers localhost host names.
6. **A fresh deployment cannot be claimed by a stranger, and after the owner only invite links let people in.** The first (owner) account needs the one-time setup link printed by `cloudhal deploy`; afterwards sign-up is closed. Invites are `chinv_` + 256 random bits, stored only as a SHA-256 hash, shown once, delivered in the URL fragment, single use (one guarded statement), revocable, bound to one email and one role, and expire (7 days by default, 1 h–14 d, Administrator invites ≤ 72 h). The invite and reset endpoints take JSON only and are rate-limited per IP; accepting refuses while another user is signed in. Tokens and hashes never appear in audit rows.
7. **Drafts stay private.** Previews require signed, expiring, site-bound tokens, are never cached, and their HTML is sandboxed (CSP `sandbox`).
8. **People stay inside their role; the server decides, never the UI.** REST is default-deny: every route declares its requirement in `ROUTE_SCOPES` (`packages/api/src/scopes.ts`) and a test fails for any undeclared route. Own-limited roles may only touch entries they (or their agents) wrote; `author` is set by the server. An Author's publish goes live only when every public change is their own, otherwise it becomes a request someone with the full power decides. Only someone who could make a call right now may approve it, and nobody approves their own request. Membership changes go through audited routes only; demotion narrows keys at once, removal revokes sessions, disables keys, cancels invites and denies pending requests. Studio's gating is cosmetic.
9. **Media cannot become a vector (RFC-0004).** The server sniffs every file's type from its bytes and refuses a declared type or extension that disagrees, active content (HTML, XML, scripts), archives and executables. Photos lose Exif/GPS, XMP, IPTC and comments by default (lossless; only people may keep them); AVIF with metadata is refused. SVG is validated and rejected rather than sanitised (no DTD or entities, allowlisted elements and attributes, no handlers, script URLs or external references), only people may upload it, and it is served under `CSP sandbox`. Every media response carries `nosniff`; data files are attachments. Blob keys are derived from validated ids (`media/<siteId>/<sha256>`), every adapter checks keys and the filesystem adapter checks containment. A media URL serves only what the published snapshot (or a preview token's target) contains.
10. **The server never fetches into private networks.** `fetch_asset_url` and `cloudhal media import-urls` take https on port 443 only, no IP literals or internal names, check every resolved address (IPv4, IPv6, mapped and NAT64 forms) against private, loopback, link-local and metadata ranges, follow at most 3 redirects with each hop re-checked, enforce size, time and content-type limits, and honour a per-site host allowlist. On Node the connection is pinned to the checked address.

## Accepted risks (alpha)
- **Skill narrowing is advisory.** A client that omits `_meta["cloudhal.skill"]` is limited only by its key's scopes. Bind skills to keys before treating them as a control.
- **Roles are deployment-wide.** A role applies to every site of the deployment; keys are not scoped to a site. Per-site roles come later (RFC-0005 open question 10).
- **Link invites leave the email unverified.** Whoever holds a link becomes the invitee; the account's email is marked unverified unless a mail sender delivered the link. A link pasted into a shared channel grants its role to whoever uses it first; links are single use, short-lived and revocable.
- **Administrators can demote or remove each other** (Ghost parity). Every change is audited and the affected person is notified.
- **Administrator-issued password reset links** (`chrst_…`, one hour, single use) let an Administrator take over a non-Owner account; they are audited, and never issued for the Owner.
- **The deployment token is root** for site data (read drafts, replace content). Keep `.cloudhal/deploy/secrets.json` private; rotation tooling is pending.
- **Preview tokens and agent keys do not expire by default** (preview links up to 7 days; keys until revoked). Revoke keys in Studio; shorter defaults are planned.
- **Approval prompts include agent-chosen titles** (shortened and quoted). Read the change list, not just the counts.
- **`auto` mode publishes without a person** within the low-risk rule. A wrong but small article change can go live; it is audited as auto-approved and one rollback away. Prefer a time-boxed elevation over a permanent `auto` key.
- **Local `cloudhal mcp` trusts the developer's MCP client** to ask the person (elicitation).
- **Workers cannot pin DNS.** On the admin Worker, `fetch_asset_url` checks names through DNS-over-HTTPS but `fetch` resolves again; a rebinding answer could differ. Cloudflare's egress has no route to the operator's private networks or cloud metadata, and every other rule still applies. Set a per-site host allowlist (`cloudhal.media.allowHosts`) for agents that fetch.
- **No malware scanning.** Uploads are type-checked, not scanned; data files are served as attachments. Attach a scanner to R2 event notifications if you need one.
- **A taken-down file may survive in browsers** that cached it under `immutable`; the edge copy is purged.
